# 📋 Gemini Nano x ScrumClock 專案管理深度整合實作計畫 (Task Plan)

> **目標**：依據 `0.doc_mg/docs/scrumclock_pm_gemini_nano_optimization.md` 藍圖，將已建置之 Web AI API 矩陣（`WebAIGateway`、`ai.writer`、`ai.summarizer`）無縫植入 `chrome_scrumclock` 專案管理功能（`BoardView.tsx`、`TaskDetailDrawer.tsx`、`ProjectManagementDemo.tsx`）。
> **核心指標**：零 API 成本、100% 離線可用、GTD 收件匣處理時間降低 80%、任務啟動摩擦趨近於零。


## 📋 階段性任務細部清單 (Detailed Tasks)

### 階段一：專案管理專用 AI 服務與邏輯層 (Phase 1)
- [ ] **Task 1.1**：建立 `chrome_scrumclock/src/features/project-management/services/taskAIEngine.ts`
  - 封裝 `triageInboxItems`：批次評估收件匣卡片，輸出推薦狀態（`next-action` / `someday`）、情境標籤與預估番茄鐘。
  - 封裝 `decomposeTask`：調用 `WebAIGateway.writeDraft`（`ai.writer`），將大型目標拆解為 3~4 個具體 Checklist 步驟。
  - 封裝 `generateDailyReview`：調用 `WebAIGateway.summarizeText`（`ai.summarizer`），自動產出日終 High-Signal 總結。
- [ ] **Task 1.2**：建立 `chrome_scrumclock/src/features/project-management/services/kanbanAuditor.ts`
  - 掃描 `in-progress` 與 `next-action` 中超過 5 天未更新之卡片。
  - 提供健康度指標（WIP 飽和度、停滯任務比率）。

### 階段二：看板 UI 元件與人機協同 (HITL) 整合 (Phase 2)
- [ ] **Task 2.1**：建立 `chrome_scrumclock/src/features/project-management/components/InboxTriageModal.tsx`
  - 呈現 Nano 批次整理之建議清單（狀態變更、標籤、番茄鐘）。
  - 支援單筆微調與「一鍵全部套用」，並以 StorageQueue 循序寫入資料庫。
- [ ] **Task 2.2**：改造 `chrome_scrumclock/src/features/project-management/components/TaskDetailDrawer.tsx`
  - 新增「⚡ Nano 拆解為番茄作戰計畫」按鈕。
  - 自動將拆解出的原子步驟寫入 `WeeklyMission.checklist`。
- [ ] **Task 2.3**：升級 `chrome_scrumclock/src/features/project-management/components/BoardView.tsx`
  - 收件匣欄位頂部新增「✨ 一鍵釐清 (Inbox Zero)」觸發按鈕。
  - 實作拖曳時的「語意 WIP 衝突提醒」彈窗。

### 階段三：日終反思與背景守護閉環 (Phase 3)
- [ ] **Task 3.1**：升級 `chrome_scrumclock/src/features/scrumclock/components/EndOfDayReview.tsx`
  - 點擊「一鍵產生今日戰報」直接調度 `TaskAIEngine`。
  - 支援將日終反思匯出為帶有 YAML Frontmatter 的 Markdown 筆記。
- [ ] **Task 3.2**：在 `chrome_scrumclock/src/background.ts` 註冊 `chrome.idle` 監聽
  - 偵測使用者閒置 15 分鐘後啟動輕量巡檢，自動建議殭屍卡片降級至 `someday`。
